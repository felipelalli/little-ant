# 23. Review and resumption checklist

## 23.1 Confirm the consolidated decisions

- [ ] The central distinction between priority and forecast is correct.
- [ ] Priority asks strict relative importance, with `?`, ordering skip, and
      `tie-break for me` carrying distinct non-equality semantics.
- [ ] Phase and effort are optional, lazy, Nature-applicable, and never
      feeding forms or hidden priority sorts.
- [ ] Raw review, archive, snapshot, and reuse behavior matches the intended
      material model.
- [ ] Multiple WIPs plus one current focus is correct.
- [ ] Impact means expected impact and uses six discrete classes.
- [ ] Impact maturity describes evidence, not probability of success.
- [ ] Effort means total work for the current scope and uses the eight-class
      versioned profile.
- [ ] Remaining effort is a conservative projection, not a moving user rating.
- [ ] Parent effort includes descendants and decomposition coverage is
      explicitly confirmed.
- [ ] TaskJuggler uses one macro per non-overlapping planning-cut node and
      saves an immutable manifest.
- [ ] The standard Pack ships a Lua TaskJuggler ReadOnlyExporter as a supported
      integration and public conformance example, while the core retains
      planning semantics, projection validation, IDs, and manifest authority.
- [ ] Estimates and imported actuals remain separate.
- [ ] Scope revision requires semantic confirmation and affects only related
      evidence.
- [ ] The REPL is a deterministic 1.0 harness with one-key finite choices,
      canonical CLI parity, and separate exact-dialog recovery state.
- [ ] Dumb REPL, powered-up REPL, and operator skill share one contextual
      interaction protocol and preserve judgment provenance.
- [ ] BrickNature and BrickTemplate remain generic, inspectable, versioned
      where applicable, and free from hard-coded domain branches.
- [ ] External feeding, semantic adoption, derived source views,
      ImportProfiles, and semantic RawShelves remain distinct.
- [ ] External completion and presence remain independent; migration uses
      explicit verification and cutover, retains historical provenance, and
      treats optional source cleanup as a separately approved destructive
      effect rather than completion.
- [ ] Little Ant Pack is the sole distribution concept; typed PackComponents
      replace a generic Plugin type or arbitrary hooks.
- [ ] Declarative and executable component kinds remain closed and
      unambiguous: BrickNature, BrickTemplate, ImportProfilePreset,
      SourceAdapter, Enricher, ReadOnlyExporter, and UIAdapter.
- [ ] Every executable Pack uses Lua 5.4 in the isolated HsLua runner under
      bounded host capabilities, including standard-Pack components, and no
      Pack code executes during replay.
- [ ] Pack HTTP is host-brokered with exact allowed hosts; credentials remain
      in the encrypted local vault and are injected by the CredentialBroker
      without exposing secrets or tokens to Lua.
- [ ] UIAdapter belongs to the 1.0 Pack protocol, consumes the canonical
      InteractionEnvelope, and cannot invent actions, weaken approval, or
      apply stale channel responses.
- [ ] Structured command responses are sparse by schema, mutators return
      compact postconditions, and complete entity or event projections remain
      explicit without hiding actionable outcomes.
- [ ] ListEntry is correctly separated from Raw and independently focusable
      Brick work.
- [ ] Opaque identity, repeated titles, canonical English, original-input
      provenance, and duplicate suspicion have the intended boundaries.
- [ ] Standing collections, recurring obligations, and practices have distinct
      lifecycle and missed-opportunity semantics.
- [ ] Practice streaks are derived, and blocked or paused practices do not
      fabricate failures.
- [ ] Comparison contradictions preserve current judgment plus history.
- [ ] All corrections accurately supersede earlier proposals.
