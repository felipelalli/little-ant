# 23. Review and resumption checklist

## 23.1 Confirm the consolidated decisions

- [ ] The central distinction between priority and forecast is correct.
- [ ] Phase describes work without becoming a hidden priority sort.
- [ ] Raw review, archive, snapshot, and reuse behavior matches the intended
      material model.
- [ ] Multiple WIPs plus one current focus is correct.
- [ ] Impact means expected impact and uses six discrete classes.
- [ ] Impact maturity describes evidence, not probability of success.
- [ ] Effort means total work for the current scope and uses the eight-class
      versioned profile.
- [ ] Remaining effort is a conservative projection, not a moving user rating.
- [ ] Parent effort includes descendants and decomposition coverage is
      explicitly confirmed.
- [ ] TaskJuggler uses one macro per non-overlapping planning-cut node and
      saves an immutable manifest.
- [ ] Estimates and imported actuals remain separate.
- [ ] Scope revision requires semantic confirmation and affects only related
      evidence.
- [ ] The REPL is a deterministic 1.0 harness with one-key finite choices,
      canonical CLI parity, and separate exact-dialog recovery state.
- [ ] Comparison contradictions preserve current judgment plus history.
- [ ] All corrections accurately supersede earlier proposals.

## 23.2 Resume discovery

- [ ] Decide impact-maturity promotion and downgrade evidence.
- [ ] Decide the assisted impact-classification dialog.
- [ ] Decide how effort confidence is represented publicly.
- [ ] Decide the REPL key grammar, palette flow, TTY behavior, and recovery
      details.
- [ ] Work through the remaining questions in chapter 19.

## 23.3 Complete design before implementation

- [ ] Review every existing Little Ant-related Brick with the user.
- [ ] Bring each accepted idea into this design through explicit questions.
- [ ] Only then mark old Bricks done, dropped, or superseded as appropriate.
- [ ] Update `little-ant.allium`, README, skill, command docs, and relevant
      projections in English.
- [ ] Validate the complete specification and documentation contract.
- [ ] Produce the implementation plan and explicit v0-to-1.0 migration plan.
- [ ] Begin coding only after separate authorization.
